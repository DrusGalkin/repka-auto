# Repka Auto

Бортовой компьютер для Repka Pi 4 под Debian/Ubuntu ARM64 с BlueZ и мобильный клиент React Native (Expo development build).

## Схема подключения

Автомобиль → ELM327 USB → Repka Pi → Bluetooth LE → Android / iPhone.
На мониторе Repka Pi открывается локальная приборная панель Chromium. Wi-Fi и интернет для просмотра данных не нужны.

Принятое аппаратное подключение — **USB ELM327**. Если ваш адаптер Bluetooth Classic, сначала настройте его как `/dev/rfcomm0` средствами BlueZ и укажите этот порт. BLE OBD2-адаптеры напрямую этим сервисом не поддерживаются. Телефон подключается к BLE-сервису Repka Auto внутри приложения; ручное сопряжение в настройках телефона не требуется.

Нужен Bluetooth-контроллер с поддержкой **BLE peripheral / advertising**, рабочий драйвер Linux и BlueZ. Наличие такого режима на конкретном образе Repka Pi не проверено. Если встроенный контроллер его не предоставляет, используйте совместимый USB BLE-донгл. Проверка: `bluetoothctl list`, `sudo btmgmt info` (LE и advertising). Сервис и экран работают без BLE в режиме `--no-ble`.

## Что реализовано

- 17 стандартных параметров: обороты, скорость, температура ОЖ и масла, нагрузка, дроссель, температура/давление впуска, MAF, топливо, напряжение ЭБУ, зажигание, коррекции смеси, давление топлива, время работы, пробег с MIL.
- Проверка поддержки PID автомобилем; отсутствие данных показывается как «—».
- Только чтение: сервис не стирает ошибки и не отправляет управляющие команды ЭБУ. Список DTC и фирменные параметры ABS/SRS/АКПП в эту версию не входят.
- Автоматическое восстановление связи с OBD2, локальный HTTP API, панель для экрана, BLE-рассылка снимков.
- Выбор устройства на телефоне, разрешения Android, автоматическое переподключение после обрыва, скрытие показаний старше 15 секунд.
- Демо-режим, systemd-автозапуск и установка киоска.

«Все статистики» зависят от марки, модели, года и ЭБУ: стандартный OBD2 не гарантирует доступ ко всем датчикам автомобиля. Опрос последовательный; скорость зависит от ELM327 и числа поддержанных PID. Временные метки требуют правильного времени на плате и телефоне.

## Установка на Repka Pi

Скопируйте папку проекта на плату. Из корня проекта:

```bash
sudo bash deploy/install.sh
ls -l /dev/serial/by-id/
sudo nano /etc/repka-auto.env
# OBD_PORT=/dev/serial/by-id/ваш-адаптер
# при необходимости OBD_BAUD=38400
sudo systemctl restart repka-auto
sudo systemctl status repka-auto
journalctl -u repka-auto -f
```

Установщик устанавливает зависимости, создаёт системного пользователя `repka-auto`, разрешает ему обращаться к BlueZ и включает сервис при загрузке. Доступ к последовательному порту — через группу `dialout`. Конфигурация по умолчанию содержит заглушку порта: обязательно замените её. При выключенном зажигании сервис повторяет подключение через 5 секунд.

Откройте на плате `http://127.0.0.1:8765/`. HTTP слушает только localhost. JSON: `/api/state`.

Для полноэкранного запуска при входе в рабочий стол установите Chromium из репозитория ОС и **от имени пользователя рабочего стола** выполните:

```bash
bash deploy/install-kiosk.sh
```

Включите автоматический вход в графический сеанс средствами вашей ОС. Без графического сеанса сервис запускается, но окно браузера не появится. Настройка автологина зависит от образа Repka OS и не изменяется установщиком.

## Мобильное приложение

Нужны Node.js и Android SDK/JDK для Android; для iOS — macOS/Xcode и настройка подписи.

```bash
cd mobile
npm ci
npm run android -- --device
# на macOS: npm run ios -- --device
```

Это нативное BLE-приложение, **Expo Go не подходит**. Сборка создаёт папки android/ios через Expo prebuild. На физическом телефоне включите Bluetooth, разрешите приложению поиск устройств, нажмите «Найти Repka Pi» и выберите Repka Auto. На Android до 12 для BLE-поиска могут потребоваться включённые службы геолокации. Нативная сборка и работа на iOS/Android здесь не проверялись; APK/IPA не приложены.

## Проверка без автомобиля

На компьютере с Python 3.10+ (без установки OBD/BLE-зависимостей):

```bash
python service/main.py --demo --no-ble
```

Откройте `http://127.0.0.1:8765/`. Для демонстрации на телефоне запустите на Linux-плате с установленными зависимостями `python service/main.py --demo` — этот режим включает BLE и помечает показания как демо. Остановите системный сервис, если порт уже занят.

```bash
python -m unittest discover -s service/tests -v
cd mobile
npm run typecheck
npm test
npx expo export --platform android
```

## Протокол BLE v1

Service UUID: `73310001-8d21-4f2a-9f10-22c26f0c0001`.
Notify characteristic: `73310002-8d21-4f2a-9f10-22c26f0c0001`.

Каждая нотификация не длиннее 20 байт: версия (1), номер снимка modulo 256, индекс фрагмента с нуля, количество фрагментов, до 16 байт UTF-8 JSON. Потерянные или переставленные фрагменты отбрасываются, следующий снимок восстанавливает поток. Максимум 4080 байт на снимок; нет предположения об увеличенном MTU. Интервал между фрагментами 35 мс, между снимками 500 мс. Это периодическая телеметрия, не поток для точных замеров разгона.

JSON: `v`, `status`, `demo`, `ts` (Unix seconds), `metrics` (PID → `[value|null, unit, measurement_timestamp]`). BLE-сервис доступен находящимся поблизости устройствам, аутентификация и шифрование на уровне приложения не реализованы. В текущей версии UUID и имя не являются проверкой личности платы.

## Проверки и ограничения

Автотесты проверяют упаковку/сборку BLE, минимальный MTU, потерю фрагментов и изоляцию снимков. На реальной Repka Pi, ЭБУ и телефоне требуется проверка: cold boot, разрешения BlueZ, реклама BLE, подписка на уведомления, отключение адаптера, выключение зажигания, выход телефона из зоны действия и возврат. Для надёжной установки в машине потребуется подходящее питание платы и корректное завершение работы при отключении питания.

Основа интеграций: [python-OBD](https://python-obd.readthedocs.io/en/latest/Connections/), [Bless](https://github.com/kevincar/bless), [react-native-ble-plx](https://dotintent.github.io/react-native-ble-plx/).

На Windows npm-скрипт перед сборкой распаковывает Android-шаблон Expo, обходя обнаруженную ошибку копирования нативных файлов. Проверены Expo prebuild и экспорт Android JS bundle; полноценная Gradle-сборка требует Android SDK.

Проверка зависимостей `npm audit` после доступных совместимых обновлений сообщает 12 замечаний (1 low, 9 moderate, 2 high) в цепочке Expo/сборочных инструментов. Автоматическое исправление требует перехода на другой major Expo; перед публичным релизом приложения этот переход и повторную проверку необходимо выполнить.
